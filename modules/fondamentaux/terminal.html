01 Fondamentaux Tech Débutant

Le terminal & Linux

Bienvenue ! On commence par l'outil de base de tout métier tech : le terminal. Tu n'en as jamais ouvert un ? Parfait — c'est exactement pour toi que ce chapitre est écrit.

Rassure-toi. Le terminal fait peur au début (un écran noir, du texte…), mais c'est juste une autre façon de parler à ton ordinateur : au lieu de cliquer sur des icônes, tu écris ce que tu veux faire. On va y aller pas à pas, avec des exercices à taper toi-même. À la fin, tu seras à l'aise pour naviguer et manipuler des fichiers.

D'abord, c'est quoi un système d'exploitation ?

Un système d'exploitation (ou OS, pour Operating System) est le programme qui fait tourner ton ordinateur : il gère l'écran, le clavier, les fichiers, les autres programmes. C'est le chef d'orchestre de la machine. Tu en utilises déjà un :

  • Windows — le plus répandu sur les PC.
  • macOS — sur les Mac.
  • Linux — gratuit, open-source, et… ce qui fait tourner la quasi-totalité des serveurs du web.
Pourquoi Linux nous intéresse

Quand ton code partira « en production » (sur un serveur, dans le cloud), il tournera presque toujours sur Linux. Et sur un serveur, il n'y a pas d'écran ni de souris : on le pilote… au terminal. Apprendre le terminal, c'est donc apprendre à parler la langue des serveurs.

Le terminal, c'est quoi ?

Le terminal (aussi appelé console ou ligne de commande) est une fenêtre où tu tapes des commandes — des ordres en texte — que l'ordinateur exécute. Une commande, c'est un mot (souvent une abréviation en anglais) suivi éventuellement d'options et d'un nom de fichier.

Les développeurs l'adorent parce qu'il est précis, rapide, automatisable et identique partout (y compris sur les serveurs sans écran).

Comment ouvrir un terminal
  • Windows — installe Git Bash (fourni avec Git, chapitre suivant) et ouvre-le. Il te donne un terminal « façon Linux », idéal pour suivre ce cours.
  • macOS — ouvre l'application Terminal (via Spotlight : Cmd + Espace, puis tape « terminal »).
  • Linux — cherche Terminal dans tes applications (souvent Ctrl + Alt + T).

Tu verras une ligne qui se termine par $ (ou %) et un curseur qui clignote : c'est le prompt, il attend ta commande.

Se repérer : le système de fichiers

Tes fichiers sont rangés dans des dossiers (aussi appelés répertoires), eux-mêmes dans d'autres dossiers. Ça forme une arborescence — imagine des classeurs dans des classeurs. À tout moment, tu te trouves « dans » un dossier : ton dossier courant.

une arborescence (exemple)
/                     <- la racine (le tout début)
└── home/
    └── alice/        <- ton dossier personnel (~)
        ├── Documents/
        ├── Images/
        └── projets/
            └── mon-site/

Trois commandes pour se déplacer là-dedans :

CommandeCe qu'elle faitMémo
pwdAffiche où tu es (le chemin du dossier courant)print working directory
lsListe ce qu'il y a dans le dossier courantlist
cd <dossier>Entre dans un dossier (change directory)cd .. remonte d'un cran
À toi de jouer Exercice

Ouvre ton terminal et tape ces commandes, une par une (valide avec Entrée) :

terminal
pwd            # où suis-je ?
ls             # qu'est-ce qu'il y a ici ?
cd ~           # va dans mon dossier personnel
ls             # regarde ce qu'il contient
cd ..          # remonte d'un dossier
pwd            # vérifie : le chemin a changé

Résultat attendu : pwd affiche un chemin comme /home/alice (ou /c/Users/alice sur Git Bash), ls affiche la liste de tes dossiers, et après cd .. le chemin s'est bien raccourci. ✅ Bravo, tu navigues !

Créer, copier, déplacer, supprimer

Maintenant, agissons sur les fichiers et dossiers :

CommandeCe qu'elle fait
mkdir <nom>Crée un dossier (make directory)
touch <fichier>Crée un fichier vide
cp <source> <destination>Copie un fichier (copy)
mv <source> <destination>Déplace ou renomme (move)
rm <fichier>Supprime un fichier (remove)
cat <fichier>Affiche le contenu d'un fichier
Crée ta première arborescence Exercice
terminal
cd ~                       # on part du dossier personnel
mkdir mon-premier-projet   # crée un dossier
cd mon-premier-projet      # entre dedans
touch notes.txt            # crée un fichier vide
ls                         # -> notes.txt
mv notes.txt journal.txt   # renomme le fichier
cp journal.txt sauvegarde.txt  # copie
ls                         # -> journal.txt  sauvegarde.txt

Résultat attendu : le dernier ls affiche deux fichiers : journal.txt et sauvegarde.txt. Tu viens de créer, renommer et copier — sans une seule souris ! 🎉

Attention avec rm !

Dans le terminal, la suppression est définitive : pas de corbeille, pas de « annuler ». rm fichier.txt efface le fichier pour de bon. Et rm -r dossier efface un dossier et tout ce qu'il contient. Vérifie toujours deux fois avant de valider — surtout ne tape jamais rm -rf / (ça tenterait d'effacer tout le système).

Un aperçu : permissions & processus

Deux notions que tu croiseras souvent — juste de quoi savoir de quoi on parle :

  • Les permissions — chaque fichier dit qui a le droit de le lire (r), l'écrire (w) ou l'exécuter (x). Tape ls -l : la colonne de gauche (ex. -rw-r--r--) décrit ces droits. C'est ce qui empêche n'importe qui de modifier n'importe quoi.
  • Les processus — chaque programme qui tourne est un processus, avec un numéro (PID). ps ou top les listent. On y reviendra ; retiens juste : « un programme en cours d'exécution = un processus ».

Quelques réflexes qui changent la vie

  • La touche Tab — complète automatiquement un nom de fichier/dossier. Tape cd mon-pre puis Tab : il complète tout seul. Un gain de temps énorme et zéro faute de frappe.
  • La flèche ↑ — rappelle les commandes précédentes (pas besoin de retaper).
  • clear — nettoie l'écran quand c'est trop chargé.
  • <commande> --help — affiche l'aide d'une commande (ex. ls --help). Ton meilleur ami pour découvrir les options.
  • Le joker * — remplace « n'importe quoi » : ls *.txt liste tous les fichiers qui finissent par .txt.

Erreurs fréquentes

Les messages que tu vas voir (et comment réagir)
  • command not found — la commande n'existe pas ou est mal orthographiée. Vérifie l'écriture (le terminal est sensible à la casse et aux espaces).
  • No such file or directory — le fichier/dossier n'existe pas là où tu es. Fais pwd et ls pour vérifier que tu es au bon endroit et que le nom est exact.
  • Permission denied — tu n'as pas le droit. On verra les permissions plus tard ; pour l'instant, c'est souvent que tu essaies de toucher un fichier système.
  • « il ne se passe rien » — beaucoup de commandes qui réussissent n'affichent rien (c'est bon signe !). Fais ls pour constater le résultat.
