Comment fonctionne le web

Que se passe-t-il vraiment quand tu tapes une adresse et appuies sur Entrée ? On soulève le capot : client/serveur, HTTP, DNS, JSON et les API.

Pourquoi c'est important. Ton code Python ne restera pas sur ta machine : il deviendra une application que d'autres utilisent via internet. Comprendre comment circule l'information sur le web est indispensable — c'est le décor de tout ce qui suit.

Client & serveur : le restaurant

Le web fonctionne par demande / réponse. Imagine un restaurant : toi, le client, tu passes commande ; la cuisine (le serveur) prépare et te renvoie le plat. Sur le web : ton navigateur (client) envoie une requête, un serveur la traite et renvoie une réponse (la page, des données…).

L'URL décortiquée

Une URL est l'adresse d'une ressource sur le web. Décomposons :

une URL
https://www.exemple.com/produits?categorie=livres
  │        │              │         │
  │        │              │         └─ paramètres (query) : des filtres
  │        │              └─ chemin (path) : quelle ressource
  │        └─ nom de domaine : quel serveur
  └─ protocole : https (sécurisé) ou http

HTTP : la langue du web

HTTP est le protocole (l'ensemble de règles) que client et serveur utilisent pour se parler. Chaque requête a une méthode qui dit quelle action on veut :

MéthodeActionAnalogie
GETLire / récupérerconsulter la carte
POSTCréerpasser une commande
PUTModifier / remplacerchanger sa commande
DELETESupprimerannuler la commande

Et chaque réponse porte un code de statut qui dit comment ça s'est passé :

CodeSensExemple
2xx✅ Ça a marché200 OK
3xx↪️ Va voir ailleurs301 Redirection
4xx🙋 Erreur de ta part404 Not Found
5xx💥 Erreur du serveur500 Server Error

Le fameux 404, c'est ça : tu demandes une page qui n'existe pas.

DNS : l'annuaire du web

On tape exemple.com, mais les serveurs se trouvent par leur adresse IP (une suite de chiffres, ex. 93.184.216.34). Le DNS est l'annuaire qui traduit le nom en adresse — comme un carnet de contacts qui associe un nom à un numéro de téléphone. Ton navigateur le fait automatiquement, en une fraction de seconde.

JSON : le format d'échange

Quand deux programmes s'échangent des données, ils utilisent le plus souvent le JSON — un format texte à la fois lisible par un humain et facile pour une machine. Il ressemble beaucoup aux dictionnaires Python :

JSON
{
  "id": 42,
  "nom": "Alice",
  "email": "alice@exemple.com",
  "actif": true,
  "roles": ["admin", "editeur"]
}

Des clés (« nom ») associées à des valeurs (texte, nombre, booléen, liste). C'est tout !

Une API REST, c'est quoi ?

Une API (Application Programming Interface) est la carte du restaurant d'un service : la liste de ce qu'il sait faire, et comment le lui demander. Le style REST organise ça autour de ressources (des noms, au pluriel) manipulées avec les méthodes HTTP :

RequêteCe qu'elle fait
GET /produitsLister tous les produits
GET /produits/42Lire le produit n°42
POST /produitsCréer un produit
DELETE /produits/42Supprimer le produit n°42

C'est exactement ce type d'API qu'on construira au chapitre 6 (le projet fil rouge) !

Tester une API avec curl

curl est un outil du terminal qui envoie des requêtes HTTP — comme un navigateur, mais en texte. Parfait pour voir ce qu'une API renvoie.

Ta première requête à une vraie API Exercice

Dans ton terminal, interroge une API publique de test :

terminal
curl https://jsonplaceholder.typicode.com/todos/1

Résultat attendu : l'API te renvoie du JSON, quelque chose comme :

réponse (JSON)
{
  "userId": 1,
  "id": 1,
  "title": "delectus aut autem",
  "completed": false
}

Tu viens de communiquer avec un serveur à l'autre bout du monde, en une commande. 🌍 (Tu peux aussi coller l'URL dans ton navigateur — même résultat.)

Erreurs fréquentes

Ce que tu croiseras
  • 404 Not Found — l'URL est fausse ou la ressource n'existe pas. Vérifie l'adresse.
  • 500 Server Error — le problème vient du serveur, pas de toi. Réessaie plus tard ou signale-le.
  • Could not resolve host — le DNS n'a pas trouvé le domaine (nom mal tapé, ou pas de connexion internet).
  • Connection refused — rien n'écoute à cette adresse/port (le serveur n'est pas démarré). On reparlera des ports au chapitre 7.
