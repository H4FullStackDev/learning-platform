Passerelle vers le DevOps

Dernier chapitre ! On empaquette ta mini-API dans un conteneur pour qu'elle tourne partout à l'identique — ton tout premier Dockerfile — et on ouvre la porte de la Formation 01.

La dernière brique. Tu sais coder, versionner, tester et isoler ton projet. Il reste à l'empaqueter pour qu'il tourne partout pareil — sur ta machine comme sur un serveur. C'est exactement là que commence le DevOps. On pose la première pierre : un conteneur.

Le problème : « ça marche chez moi »

Ton API marche sur ton ordinateur. Mais sur celui d'un collègue, ou sur un serveur ? Version de Python différente, dépendance manquante, config qui change… La phrase la plus célèbre de l'informatique : « pourtant ça marche chez moi ! ». On va la faire disparaître.

C'est quoi un conteneur ?

Un conteneur est une boîte qui contient ton app et tout ce dont elle a besoin pour tourner (Python, Flask, ton code, la config). L'analogie : un conteneur maritime — peu importe le bateau, le camion ou le pays, la boîte reste identique et son contenu voyage sans surprise. Docker est l'outil qui fabrique et lance ces boîtes.

Avant de commencer

Installe Docker Desktop depuis docker.com et lance-le. Vérifie avec docker --version. On voit juste le strict nécessaire ici : la Formation DevOps y consacre un chapitre entier.

Ton premier Dockerfile

Un Dockerfile est la recette de ta boîte. Crée un fichier nommé Dockerfile (sans extension) à côté de ton app.py :

Dockerfile
FROM python:3.12-slim        # on part d'une base Python légère
WORKDIR /app                 # dossier de travail dans la boîte

COPY requirements.txt .      # on copie d'abord la liste des dépendances
RUN pip install -r requirements.txt   # et on les installe

COPY . .                     # puis on copie tout le code

EXPOSE 5000                  # on documente le port utilisé
CMD ["python", "app.py"]     # la commande qui démarre l'app
Une petite retouche à ton app.py

Dans un conteneur, ton app doit écouter sur 0.0.0.0 (toutes les interfaces) pour être joignable de l'extérieur — sinon elle ne parle qu'à l'intérieur de la boîte. Modifie la dernière ligne :

app.run(host="0.0.0.0", port=port)   # au lieu de host implicite 127.0.0.1

Construire & lancer ta boîte

Ton app dans un conteneur Exercice
terminal
docker build -t mini-api .      # fabrique l'image (la boîte) à partir du Dockerfile
docker run -p 5000:5000 mini-api  # lance la boîte, port 5000 relié à ta machine

# Dans un AUTRE terminal :
curl http://localhost:5000/taches

Résultat attendu : ton API répond… mais elle tourne maintenant dans un conteneur, avec sa propre version de Python et ses dépendances. Cette même boîte tournerait à l'identique sur n'importe quel serveur. 📦🎉 Tu viens de faire du DevOps !
