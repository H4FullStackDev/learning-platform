Projet fil rouge : une mini-API

On assemble tout ce qu'on a appris — Python + SQLite + le web — pour construire une vraie petite API. C'est LE projet qu'on gardera et fera évoluer jusqu'à la fin de la formation.

Le moment où ça devient concret. Jusqu'ici, chaque brique était isolée. Ici, on les assemble pour créer une API de tâches (une petite to-do list) que n'importe quel programme pourra interroger via HTTP. On garde ce projet pour les chapitres suivants (réseau, dépendances, tests, Docker) — et jusque dans la Formation DevOps pour apprendre à le déployer.

Ce qu'on va construire

Une API REST (chapitre 4) qui gère des tâches, avec les 4 opérations « CRUD » :

RequêteAction
GET /tachesLister toutes les tâches
GET /taches/<id>Lire une tâche
POST /tachesCréer une tâche
DELETE /taches/<id>Supprimer une tâche

On utilise Flask (un mini-framework web Python, très simple) et SQLite (la base-fichier du chapitre 5).

Installer Flask

terminal
pip install flask
# pip est le "magasin d'applications" de Python : il installe des bibliothèques

On verra au chapitre 8 comment isoler proprement ces installations par projet (les environnements virtuels). Pour l'instant, cette commande suffit.

Étape 1 — Le squelette

Commençons par le plus petit serveur qui marche. Crée un fichier app.py :

app.py
from flask import Flask

app = Flask(__name__)          # on crée l'application

@app.route("/")                # quand on visite l'adresse "/"
def accueil():
    return "Mon API fonctionne !"

if __name__ == "__main__":
    app.run(debug=True, port=5000)   # démarre le serveur sur le port 5000
Lance ton premier serveur Exercice
terminal
python app.py
# -> Running on http://127.0.0.1:5000

Ouvre http://localhost:5000 dans ton navigateur (ou curl http://localhost:5000 dans un autre terminal). Tu dois voir « Mon API fonctionne ! ». 🎉 Ton ordinateur est devenu un serveur web ! Laisse-le tourner ; pour l'arrêter, fais Ctrl+C.

Étape 2 — Brancher SQLite

On ajoute deux fonctions : une pour se connecter à la base, une pour créer la table au démarrage.

import sqlite3

def get_db():
    conn = sqlite3.connect("taches.db")
    conn.row_factory = sqlite3.Row   # pour lire les lignes comme des dictionnaires
    return conn

def init_db():
    conn = get_db()
    conn.execute(
        "CREATE TABLE IF NOT EXISTS taches "
        "(id INTEGER PRIMARY KEY, titre TEXT, faite INTEGER DEFAULT 0)"
    )
    conn.commit()
    conn.close()

Étape 3 — Les routes CRUD

Chaque route est une fonction Python décorée par @app.route(...). On y écrit du SQL (chapitre 5) et on renvoie du JSON (chapitre 4) avec jsonify.

Le code complet — app.py

app.py
from flask import Flask, request, jsonify
import sqlite3

app = Flask(__name__)

def get_db():
    conn = sqlite3.connect("taches.db")
    conn.row_factory = sqlite3.Row
    return conn

def init_db():
    conn = get_db()
    conn.execute(
        "CREATE TABLE IF NOT EXISTS taches "
        "(id INTEGER PRIMARY KEY, titre TEXT, faite INTEGER DEFAULT 0)"
    )
    conn.commit()
    conn.close()

# Lister toutes les tâches
@app.route("/taches", methods=["GET"])
def lister():
    conn = get_db()
    lignes = conn.execute("SELECT * FROM taches").fetchall()
    conn.close()
    return jsonify([dict(l) for l in lignes])

# Lire une tâche par son id
@app.route("/taches/<int:id>", methods=["GET"])
def lire(id):
    conn = get_db()
    ligne = conn.execute("SELECT * FROM taches WHERE id = ?", (id,)).fetchone()
    conn.close()
    if ligne is None:
        return jsonify({"erreur": "Tâche introuvable"}), 404
    return jsonify(dict(ligne))

# Créer une tâche
@app.route("/taches", methods=["POST"])
def creer():
    data = request.get_json()
    conn = get_db()
    cur = conn.execute("INSERT INTO taches (titre) VALUES (?)", (data["titre"],))
    conn.commit()
    nouvel_id = cur.lastrowid
    conn.close()
    return jsonify({"id": nouvel_id, "titre": data["titre"], "faite": 0}), 201

# Supprimer une tâche
@app.route("/taches/<int:id>", methods=["DELETE"])
def supprimer(id):
    conn = get_db()
    conn.execute("DELETE FROM taches WHERE id = ?", (id,))
    conn.commit()
    conn.close()
    return jsonify({"message": "Tâche supprimée"})

if __name__ == "__main__":
    init_db()
    app.run(debug=True, port=5000)
Le ? dans les requêtes SQL

On écrit WHERE id = ? avec un ?, puis on passe la valeur à part ((id,)). C'est une requête paramétrée : ça évite une faille de sécurité classique (l'injection SQL). Ne colle jamais une valeur reçue directement dans une requête — on approfondira côté sécurité plus tard.

Tester ton API

Relance python app.py, puis, dans un autre terminal, teste chaque route :

Fais vivre ton API Exercice
terminal
# Créer une tâche (POST avec du JSON)
curl -X POST http://localhost:5000/taches \
  -H "Content-Type: application/json" \
  -d '{"titre": "Apprendre le DevOps"}'
# -> {"faite":0,"id":1,"titre":"Apprendre le DevOps"}

# Lister toutes les tâches
curl http://localhost:5000/taches
# -> [{"faite":0,"id":1,"titre":"Apprendre le DevOps"}]

# Lire la tâche 1
curl http://localhost:5000/taches/1

# Supprimer la tâche 1
curl -X DELETE http://localhost:5000/taches/1
# -> {"message":"Tâche supprimée"}

Résultat attendu : chaque commande renvoie du JSON. Tu viens de construire une vraie API qui crée, lit et supprime des données en base ! 🚀 Un fichier taches.db est apparu à côté de ton app.py : c'est ta base SQLite.

Erreurs fréquentes

Les blocages du débutant
  • ModuleNotFoundError: No module named 'flask' — Flask n'est pas installé (ou pas dans le bon environnement). Refais pip install flask.
  • Address already in use (port 5000) — un serveur tourne déjà sur ce port. Arrête l'ancien (Ctrl+C) ou change le port=. On expliquera les ports au chapitre 7.
  • La page ne répond pas — as-tu bien lancé python app.py ? Le serveur doit rester ouvert dans son terminal ; teste depuis un second terminal.
  • Erreur sur le POST — n'oublie pas l'en-tête Content-Type: application/json et des guillemets valides dans le -d.

Bravo — tu as une vraie application qui tourne ! Elle écoute sur localhost:5000… mais que veulent dire « localhost » et « port 5000 » ? C'est exactement le sujet du prochain chapitre : le réseau pour développeurs.
