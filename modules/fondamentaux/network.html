Réseau pour développeurs

Ton API tourne sur « localhost:5000 »… mais qu'est-ce que ça veut dire ? Juste ce qu'il faut de réseau pour comprendre, tester et débugger tes applications.

Pas besoin d'être ingénieur réseau. Comme développeur, tu as besoin de quelques notions clés : adresses IP, ports, et savoir lire une erreur réseau. On les découvre en s'appuyant sur la mini-API du chapitre 6, qui tourne justement sur le réseau de ta machine.

L'adresse IP : l'adresse d'une machine

Chaque machine sur un réseau a une adresse IP — comme une adresse postale qui permet de la retrouver. Par exemple 93.184.216.34. Deux adresses spéciales à connaître :

  • 127.0.0.1 (alias localhost) — ta propre machine. Quand ton API dit « Running on 127.0.0.1 », elle ne parle qu'à toi, en local. C'est « chez moi ».
  • Les IP privées (ex. 192.168.x.x) — les machines de ton réseau local (box, ordis, imprimante). Les IP publiques sont visibles depuis internet.

Les ports : les portes d'une machine

Une machine fait tourner plusieurs services en même temps. Comment les distinguer ? Grâce aux ports. L'analogie : si l'IP est l'adresse d'un immeuble, le port est le numéro d'appartement. localhost:5000 = « l'appartement 5000 de ma machine » — c'est là qu'écoute ta mini-API.

PortService habituel
80HTTP (web non sécurisé)
443HTTPS (web sécurisé)
22SSH (connexion à distance à un serveur)
5000notre mini-API Flask (par défaut)

Une machine a 65 535 ports possibles. Un seul service peut écouter sur un port donné à la fois — d'où l'erreur « port déjà utilisé » du chapitre 6.

TCP vs UDP

Deux façons d'acheminer les données :

TCP (fiable)

Comme un appel téléphonique : on établit la connexion, on vérifie que tout arrive, dans l'ordre. Un peu plus lent, mais sûr. Le web (HTTP) utilise TCP.

UDP (rapide)

Comme crier un message : on envoie sans vérifier la réception. Plus rapide, mais des paquets peuvent se perdre. Utilisé pour la vidéo, le jeu en ligne.

Lire une erreur réseau

Quand une connexion échoue, le message te dit presque toujours pourquoi :

ErreurTraductionQue faire

timeoutLa machine ne répond pas (à temps)Machine éteinte, ou pare-feu qui bloque
Could not resolve hostLe DNS ne connaît pas ce nomDomaine mal tapé, ou pas d'internet

Erreurs fréquentes

Les confusions classiques
  • « curl localhost marche, mais pas depuis mon téléphone » — localhost = la machine locale. Un autre appareil doit viser l'IP de ton PC sur le réseau (ex. 192.168.1.20:5000), pas localhost.
  • Address already in use — deux programmes veulent le même port. Ferme l'ancien, ou change de port.
  • Un pare-feu qui bloque — sur certains réseaux, un port peut être fermé par sécurité. Teste d'abord en local.
