02 Fondamentaux Tech Débutant

Git & le versioning

Git, c'est la machine à remonter le temps de ton code : chaque étape est sauvegardée et tu peux toujours revenir en arrière. C'est l'outil que tu utiliseras tous les jours.

Le problème que ça règle. Tu connais sûrement le rapport_final_v2_vraiment_final_CORRIGÉ.docx ? Git supprime ce chaos : il garde l'historique complet de ton projet, te laisse revenir à n'importe quel moment, et permet à plusieurs personnes de travailler ensemble sans s'écraser.

C'est quoi « versionner » ?

Versionner, c'est enregistrer des points de sauvegarde de ton projet au fil du temps — comme les sauvegardes dans un jeu vidéo. Chaque sauvegarde s'appelle un commit : une « photo » de tous tes fichiers à un instant donné, avec un petit message qui décrit ce que tu as fait.

Git est l'outil qui gère ces sauvegardes sur ta machine. GitHub (qu'on verra plus bas) les héberge sur le cloud.

Installer & configurer Git (une seule fois)

Installe Git depuis git-scm.com (sur Windows, ça installe aussi Git Bash, le terminal du chapitre 1). Puis dis-lui qui tu es — ce nom apparaîtra sur tes sauvegardes :

git config --global user.name "Ton Nom"
git config --global user.email "toi@exemple.com"

Le workflow de base : 3 zones

Enregistrer un commit se fait en deux temps. Imagine que tu prépares un colis : d'abord tu mets les objets dans le carton (git add), puis tu l'expédies avec une étiquette (git commit). Git a donc trois « zones » :

Ton dossiertu modifies
git add
Le cartonstaging
git commit
L'historiquesauvegardé ✓
Ton premier dépôt & ton premier commit Exercice

Dans ton terminal, reprends le dossier du chapitre 1 (ou crées-en un) :

terminal
cd ~/mon-premier-projet    # va dans ton projet
git init                   # transforme le dossier en dépôt Git
git status                 # que voit Git ? (des fichiers "non suivis")
git add .                  # mets TOUT dans le carton (le "." = tout)
git commit -m "Premier commit"   # expédie avec une étiquette
git log --oneline          # regarde ton historique : ta sauvegarde est là !

Résultat attendu : git log --oneline affiche une ligne avec un code (le hash) et ton message « Premier commit ». 🎉 Ton projet a maintenant une mémoire.

Les commandes essentielles à retenir :

CommandeCe qu'elle fait
git statusOù j'en suis ? (ta commande la plus utilisée)
git add <fichier>Met un fichier dans le carton (ou git add . pour tout)
git commit -m "message"Enregistre une sauvegarde
git logAffiche l'historique des commits
git diffMontre ce que tu as changé depuis le dernier commit

Les branches

Une branche est une ligne de travail parallèle — un brouillon où tu peux tester une idée sans toucher à ta version principale (main). Quand ça marche, tu fusionnes (merge) ton brouillon dans main. Sinon, tu jettes la branche, et main n'a jamais été abîmé.

terminal
git switch -c nouvelle-idee   # crée une branche ET va dedans
# ... tu modifies, tu add, tu commit sur cette branche ...
git switch main               # reviens sur la branche principale
git merge nouvelle-idee       # fusionne ton travail dans main

On approfondit énormément les branches (stratégies, conflits) dans la Formation DevOps. Ici, retiens juste le principe : brancher pour expérimenter, fusionner quand c'est prêt.

GitHub : ton code dans le cloud

Jusqu'ici, tout vit sur ta machine. GitHub héberge tes dépôts en ligne : une sauvegarde de sécurité, un moyen de travailler à plusieurs, et ta vitrine publique (les recruteurs le regardent !). Le lien entre ta machine et GitHub :

CommandeCe qu'elle fait
git clone <url>Télécharge un dépôt existant depuis GitHub
git pushEnvoie tes commits locaux vers GitHub
git pullRécupère les commits des autres depuis GitHub
Publie ton projet sur GitHub Exercice

1. Crée un compte gratuit sur github.com. 2. Clique « New repository », nomme-le mon-premier-projet, valide. 3. GitHub te donne des commandes : colle-les dans ton terminal (elles ressemblent à ça) :

terminal
git remote add origin https://github.com/ton-pseudo/mon-premier-projet.git
git branch -M main
git push -u origin main    # envoie ton code sur GitHub

Résultat attendu : rafraîchis la page GitHub — tes fichiers y sont ! Ton code est maintenant sauvegardé dans le cloud. ✅

Travailler à plusieurs : la Pull Request

Quand plusieurs personnes contribuent, on ne pousse pas directement sur main. Le workflow simple :

  1. Tu crées une branche pour ta modification.
  2. Tu la pousses sur GitHub.
  3. Tu ouvres une Pull Request (PR) : « voici ce que je propose d'ajouter à main ».
  4. Un collègue relit (code review) et commente.
  5. Une fois validé, on fusionne la PR dans main.

C'est la base de la collaboration moderne. La Formation DevOps y consacre un chapitre entier (revue de code, protections de branche…).

Erreurs fréquentes

Les blocages classiques
  • fatal: not a git repository — tu n'es pas dans un dépôt. Fais git init, ou vérifie que tu es dans le bon dossier (pwd).
  • nothing to commit, working tree clean — il n'y a rien de nouveau à sauvegarder (tu n'as rien modifié, ou tu as oublié git add).
  • Author identity unknown — tu n'as pas configuré ton nom/email (voir plus haut, git config).
  • push rejeté (updates were rejected) — quelqu'un a poussé avant toi. Fais d'abord git pull, puis git push.
